## 目标

将已经验收的候选安全切换到生产，并验证旧入口、资源与学习记录仍可继续使用。

本包用于 Phase 1 的首次正式上线、Phase 2 的工具/内容/HSK 增量发布及 Phase 3 的账号/订阅发布，每次绑定独立 releaseId。Phase 1 只有实际部署和线上冒烟通过才算完成上线目标；不将 HF-09 候选通过视作已经上线。

## 前置材料

- HF-17 manifest/验收/回滚证据、生产现状只读核验、备份与主机规则。
- 用户对本次发布范围/窗口的明确授权；若已有会话证据可直接使用，不重复索要。

所有相对源码路径以项目根目录为基准；先读 [基线证据](../BASELINE.md)。如果前置交付缺失，先记录精确缺项，不能把未完成依赖视为已通过。后续实施可采用等价目录，但须在交付记录里更新映射。

## 涉及范围

- 生产 URL/资源/数据库兼容迁移、环境与索引切换、实际部署、上线检查/回滚、交接。

## 实施步骤

1. 只读核对线上实际部署/URL/域名规范/资源/账号schema，与静态盘点差异写回 manifest；不假定主目录就是当前线上。
2. 准备并校验静态备份、旧键只读导入、同域 /zh/ 与旧 story query 兼容；仅本次启用数据库时准备其 expand/migrate 策略与备份，Phase 1/2 不等待账号后端。
3. 验证 /index.html→/zh/ 建议符合实际历史页面与主机规则；显式永久跳转、保留必要 query、无循环；资源 URL 继续可读。
4. 候选包/验收/窗口明确后检查授权；没有授权时交可审阅包并等待最终部署指令，不提前切换。
5. 执行获授权的最小发布步骤，启用成熟页面索引，保留 staging 保护；收费只在单独明确允许范围内启用。
6. 发布后立即验证首页/免费学习/账号（若启用）/中文八课/旧资源与 HTTP；失败按 runbook 回滚，留存新事件。
7. 交接 24 小时、7 天和后续索引观察；不把排好清单当成已完成观察，不自动建定时任务。

- 审实际部署日志/版本和候选 hash；对生产 smoke 失败立即依既定回滚规则处置。
