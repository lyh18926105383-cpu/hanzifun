## 实施步骤

1. 写 release manifest：Phase 1 core 必含 HF-01～09 并继续交 HF-18 上线；Phase 2 使用 culture 工具 ID、editorial 文章/打印批次、hsk-batch 版本/级别绑定具体验收；Phase 3 accounts 含 HF-10/11、billing 含 HF-16，教师组卡仅选入时要求 HF-15。首个批次通过不把整个未完成包标 complete。
2. 冻结代码与数据，验证未选择能力的 UI/路由诚实、索引关闭，不产生死链/假承诺。
3. 验当次受影响的关键旅程、旧中文八课/108位置、三种记录迁移、许可/HSK 限定使用范围、元信息/性能/可访问性；不对未改课程重复制作媒体。Tier 2/Tier 1 都可索引，视觉增强数量不是发布门槛。
4. 若含账号/支付，执行越权/断网/冲突/删除/备份恢复及支付签名等针对性检查。
5. 在隔离环境演练切换与 10 分钟静态回滚；只有启用账号数据库时才验其向后兼容与备份。Phase 1/2 静态发布不能被尚未建设的后端阻塞；保护新产生事件，不能靠清库恢复。
6. 将未解决的关键缺陷留为阻断，完成候选包和简明发布说明。

## 验收条件

- [ ] 清单中的每个 feature 都有对应通过的任务与版本证据；缺包不能以 UI 开关掩盖已售卖承诺。
- [ ] 核心路径、旧课/记录、鉴权、数据许可和索引无阻断；环境没有生产秘密泄漏。
- [ ] 恢复演练可重复，保留旧静态包和数据；回滚不清除新用户事件。
- [ ] 报告区分已测、未测和需用户授权的上线动作，不写“全部完成”掩盖未授权部署。
- [ ] 已完成工具/文章/HSK 等级能按批独立放行；Tier 2、HSK 范围记录与六 FAQ 符合 SPEC，不等待黄金版配额、HF-11 或未选中的扩展。

- 运行本次 manifest 对应测试矩阵，读取报告而非仅看命令退出码。
- 真实等价托管环境中检查 HTTP 状态、query、canonical、缓存/音视频 Range；本地服务器结果不足以代替。
- 必要的故事回归先重读故事流程/故事板并完成适用人工确认；媒体不重生成。

记录命令/结果、测试环境与日期、代码/数据版本、适用截图和尚未验证项。测试必须对准行为风险；旧测试和新验收分别记录，不扩大成无关施工。
