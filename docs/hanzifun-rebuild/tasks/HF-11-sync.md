## 目标

使本机已确认的学习事件可靠进入正确账号，并在跨设备/断网/冲突中收敛。

## 前置材料

- 真实身份/权限与 Repository、interval-v1、三种旧记录适配器、API 规范。
- 两浏览器/设备测试用户、可控网络/时间与大批量事件夹具。

所有相对源码路径以项目根目录为基准；先读 [基线证据](../BASELINE.md)。如果前置交付缺失，先记录精确缺项，不能把未完成依赖视为已通过。后续实施可采用等价目录，但须在交付记录里更新映射。

## 涉及范围

- outbox/changes cursor、事件去重、投影、冲突、导入确认、同步状态、导出删除全流程。

## 非目标

- 不上传其他账号 pending 数据；不覆盖整份客户端状态；不以客户端时间决定所有冲突。

## 明确交付物

- 同步 API 与数据库约束/事务、离线 outbox、分页变化与 tombstone。
- 游客导入预览与幂等批次、账号切换隔离、导出/删除落地。
- docs/hanzifun-rebuild/acceptance/phase-3-accounts.md：两设备/冲突/权限/恢复证据与运维说明；本包不代表付费订阅已完成。

## 实施步骤

1. 先落本机事务再发 outbox，按服务器 ack 清除；实现重试/会话过期/partial rejection。
2. 以 userId+eventId 唯一去重，服务器 revision 驱动调度，stale known 不重复升级；stale again 按 SPEC 保守处理并告知冲突。
3. 保存服务器序号和有效发生时间，处理异常设备时间；拉取 changes 后本机投影收敛。
4. 收藏 tombstone 防旧设备复活删除；重复导入不累加，用户可暂不合并游客记录。
5. 完成 A/B 换号、删除账号后 pending 拒收、导出完整数据、失败后恢复。
6. 按 Phase 3 的账号关口执行跨设备真实旅程，记录性能、备份恢复和剩余限制，交 HF-16 接入订阅；保留已发布静态工具与匿名本机学习能力。

## 验收条件

- [ ] 稳定网络下 100 pending 事件 10 秒内收敛；重复/乱序/断网重发不丢、不多计。
- [ ] 双端同一 revision 不推进两级，冲突可解释；相同服务器日志重放一致，两端最终相同。
- [ ] 取消游客导入保持两边原状；导入旧摘要不覆盖账号已有排程；删除收藏不被 stale save 复活。
- [ ] A 的 outbox/缓存不进入 B，账号删除后不会因离线恢复复活；导出/删除行为与说明一致。

## 验证方法

- 本机和集成测试覆盖冲突矩阵、时间偏差、幂等和数据库事务失败。
- 两独立浏览器上下文完成游客→登录→导入→异端查看→离线双端→恢复→退出/切号→删除。
- 以 1,000 卡/10,000 事件夹具测同步/摘要与完整导出；恢复演练不使用生产用户数据。

记录命令/结果、测试环境与日期、代码/数据版本、适用截图和尚未验证项。测试必须对准行为风险；旧测试和新验收分别记录，不扩大成无关施工。
