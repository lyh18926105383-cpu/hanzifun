## 目标

用受验证的身份服务建立真实成人/家长/教师账号与同源授权边界。

## 前置材料

- Phase 1 验收、D-01/D-02 的地区/预算/运营信息；官方最新身份服务资料。
- Phase 2 已上线的工具/内容/HSK 批次记录，及 D-05 的自然访问、练习/回访、跨设备需求与阶段启动依据；每天数百访客为参考而非自动触发阈值。
- SPEC API/会话契约、账号表/RLS 原则；原型 Sign in 仅作视觉参考。

所有相对源码路径以项目根目录为基准；先读 [基线证据](../BASELINE.md)。如果前置交付缺失，先记录精确缺项，不能把未完成依赖视为已通过。后续实施可采用等价目录，但须在交付记录里更新映射。

## 涉及范围

- 服务选型 ADR、测试配置、Google OAuth/邮箱 magic link 或 OTP、会话/退出、资料/导出删除基础、权限。

## 非目标

- 不建立儿童独立账号；不自建密码数据库；不将登录成功等同学习记录已同步。

## 明确交付物

- docs/hanzifun-rebuild/decisions/auth.md：服务、地区、费用边界、cookie/token 策略及备份能力。
- 测试环境 auth/BFF 路由、会话与 RLS 策略、schema migration、密钥变量说明（无值）。
- 真实登录/取消/错误/退出 UI；隐私/支持信息及导出删除接口基础。

## 实施步骤

1. 确认地区/预算/主体，评估推荐 Auth/Postgres + Worker；先完成可审阅方案和本地适配，外部采购不得凭空授权。
2. 配置回调 allowlist、OAuth state/PKCE、cookie/CSRF/限流；优先提供商 SDK，不手写 token 验证捷径。
3. 实现 Google 与邮箱流程、错误/取消/过期/重试；账户链接需验证身份，不仅看邮箱相同。
4. 所有私人表按 auth subject 授权；配置 RLS/写入检查，普通请求不使用越权 service-role 绕过。
5. 加入资料、退出/撤销会话、导出删除基础；共享设备缓存不串号；服务端密钥不进客户端或日志。
6. 无生产凭据时保留本地可测路径并标环境阻断，不把假登录截图算完工。

## 验收条件

- [ ] Google 与邮箱在已配置测试环境真实往返成功，取消/过期/错误有可恢复状态。
- [ ] 未登录/A/B 账号读写隔离通过，客户端伪造 userId 不生效；个人响应不进公共缓存。
- [ ] 退出后其他人不能看到上一账号的学习缓存；身份链接与删除操作不可被越权调用。
- [ ] 隐私/地区/预算和主体信息明确；无密钥出现在构建或日志。

## 验证方法

- 认证集成测试：有效/过期/重放回调、CSRF、跳转注入、限流、A/B 越权读写。
- 浏览器测试 Google 取消/回调、邮箱一次性码、退出后后退/刷新、会话过期。
- 检查 bundle、日志与公开输出不含密钥；RLS 包含 SELECT/INSERT/UPDATE/DELETE。

记录命令/结果、测试环境与日期、代码/数据版本、适用截图和尚未验证项。测试必须对准行为风险；旧测试和新验收分别记录，不扩大成无关施工。
