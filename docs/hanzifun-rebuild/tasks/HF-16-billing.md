## 目标

在商业方案明确后完成可验收的支付/退款/权益闭环，生产收款另受发布授权控制。

## 前置材料

- D-04 的价格、币种、主体、免费边界、税/退款/取消规则与服务商决定。
- 已上线或本次计划发布的付费功能清单；身份/权限/同步、提供商官方文档。

所有相对源码路径以项目根目录为基准；先读 [基线证据](../BASELINE.md)。如果前置交付缺失，先记录精确缺项，不能把未完成依赖视为已通过。后续实施可采用等价目录，但须在交付记录里更新映射。

## 涉及范围

- Pricing 真实文案、测试 hosted checkout、签名 webhook、权益、账单管理与退款撤权。

## 非目标

- 不自行决定售价或签订商户服务；不使用真实银行卡做测试；不在本包自动接通生产收款。

## 明确交付物

- pricing/entitlements 配置及商业决策记录；提供商版本与测试环境说明。
- 支付/账单接口、事件幂等表、权益状态机、退款/取消流程和测试证据。
- 故障/乱序/重复 webhook 处置手册与生产切换清单。

## 实施步骤

1. 先将免费/付费能力、价格和经营信息做成可审阅方案；核验所选提供商地区与官方费用/限制。
2. 选择 hosted checkout，服务端创建订单/校验价格与 user；不接受客户端任意金额/权益。
3. 校验 webhook 签名及幂等，处理订阅续费/失败/取消/退款/乱序；前端 return URL 只查服务端状态。
4. 权益服务端授予与撤销，明确取消后何时失效；付费数据保存/导出/账户删除与必要账务保留分开。
5. 用测试模式演练全部状态，完成 Pricing/条款/退款说明，与未发布功能承诺核对。

## 验收条件

- [ ] 测试付款与失败/取消/退款状态正确；重复或乱序事件不会重复授予或错误复活权益。
- [ ] 前端伪造成功地址、金额、计划或 userId 不能开通；签名无效事件拒绝。
- [ ] Pricing 展示实际选择的价格/币种/税费规则与免费范围，无虚构“已付费用户”。
- [ ] 生产付款仍关闭，直到 HF-18 所需明确授权与提供商配置就绪。

## 验证方法

- 提供商官方测试场景+webhook 签名/重放/乱序/退款测试；A/B 权限隔离。
- 浏览器新用户购买/取消/失败恢复/查看账单/取消订阅路径（测试模式）。
- 检查日志与数据无卡号等不应保存的支付敏感信息。

记录命令/结果、测试环境与日期、代码/数据版本、适用截图和尚未验证项。测试必须对准行为风险；旧测试和新验收分别记录，不扩大成无关施工。
