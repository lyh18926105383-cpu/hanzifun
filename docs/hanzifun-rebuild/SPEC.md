## 1. 产品目标与阶段

面向海外用户，以英文为主、保留中文学习入口。服务三类人群：海外华人家庭与儿童；来华旅行、文化兴趣及商务外贸人群；专业学习汉语的学生与教师。共享一套汉字、词、实用短句数据，以视觉化记忆、闪卡回忆、真实场景学习连接三条路径。

首要成功路径是：**搜索汉字 → 理解读音、字义和视觉记忆线索 → 查看笔顺 → 练习闪卡 → 保存并再次找到学习记录**。不以页面数量、账号注册量或生成内容量代替闭环是否可用。

| 阶段 | 必须交付 | 阶段出口 |
|---|---|---|
| Phase 1 首发上线 | 基线整合；126 字至少达到 Tier 2，优先增强 30–50 字至 Tier 1；Information、独立笔顺与拼音表；四组本机闪卡/复习；餐厅与商务两场景；HSK 2.0/3.0 各首级；中文兼容与 SEO | HF-01～09 → HF-17 → HF-18；以实际生产上线、成熟页开放索引和线上冒烟检查为阶段出口，不停在候选包 |
| Phase 2 引流工具与内容 | 起名、生肖、菜单、纹身四个浏览器工具；3–5 篇正式 Blog；HSK 先扩至两版 2 级，再按级扩充；正式打印资源 | HF-12/13/14 解除 HF-11 依赖，各批完成即复用 HF-17/18 发布，不等待全部高级 HSK |
| Phase 3 账号、同步与订阅 | 在真实使用需求形成后，完成成人/家长/教师登录、游客导入、跨设备同步与付费订阅；教师私人组卡为可选扩展 | HF-10 → HF-11 → HF-16，按范围复用 HF-17/18；HF-15 可选，不作为前两阶段或订阅首发的必选前置 |
| 各次发布 | 明确本次版本、内容批次、索引范围、回归与回滚 | HF-17/18 按 releaseId 重复执行，首发后不把所有任务状态重置或全量重验 |

Phase 1 内仍按基线 → 学习闭环 → 首发验收推进；HF-09 是上线前检查，不是整阶段完成。Phase 1/2 使用静态托管、构建时数据处理和浏览器运算，不引入账号数据库或应用后端作为前置。AI 辅助内容可在编辑时生成，公开页面不依赖付费生成 API。

Phase 3 启动以 Phase 2 已有上线成果和真实用户需求为依据。每天数百自然访客是参考信号，不是承诺或单日自动触发线；建议观察连续约 28 天的自然访问、开始/完成本机练习、回访及跨设备需求，区分搜索点击、访客和学习活跃。记录依据后安排账号投入；不等待全部高级 HSK，也不因没有量化数据而虚构日活。

首发不包含：儿童独立身份系统、学校班级/作业平台、完整汉语课程、故事课新增或英文化、手写识别、全离线安装、OCR、自动趋势采集、个性化 AI 算命、订阅收费。后两阶段不阻塞第一阶段上线。

书法目前暂不规划，不预设书法栏目或后续交付日期。Kanji 作为单字补充信息，不扩展为日语课程、独立 Kanji 字典或日语练习系统。参考站调研中的独立部件专题、词语详情页、简繁导读等仍属候选，不因接受单字页建议而自动加入首发。

## 5. REQ-04｜技术方案与目录边界

建议默认继续使用 **Node 静态生成 + 原生浏览器 ES modules + Cloudflare 静态资源**。这是根据现有项目和已确认原型作出的取舍：无需为 77 类预览页立即迁移 React/Next.js；公开学习内容可预渲染，交互模块按页加载。现有中文 UMD 代码保持独立运行。

建议目录（由 HF-01 契约冻结，名称可以等价调整并同步文档）：

```text
site/                 英文布局、模板、routes manifest
src/learning/         纯函数调度、事件、仓储契约
src/client/           搜索、笔顺、闪卡、学习中心交互
src/server/           Phase 3 起的同源 API / auth BFF
data/                 已许可的标准化数据、版本及覆盖清单
content/              审核过的场景、文章、教学联想
public/               新英文站公开资源，文件名带版本或内容哈希
legacy/               经 HF-01 整合后的中文源文件（是否移动由迁移实现确定）
scripts/              数据导入、构建、路由/许可/覆盖检查
tests/                保留旧测试，增加新模块与端到端测试
docs/hanzifun-rebuild/ 规范、任务、证据与决策记录
dist/                 构建产物，禁止手工维护
```

不得在先前尚未合并的 root `index.html`/`styles.css`/`story.js` 上同时施工。英文资源与中文资源使用不同前缀，避免 `/app.js`、`/styles.css` 同名冲突。构建需可重复、清理过期输出、生成 route/content/data manifest；第三方包精确锁版本并提交锁文件。不从运行时 `@latest` CDN 获得关键数据。

Phase 3 后端建议：**Cloudflare Worker 同源 BFF + Supabase Auth/Postgres**，以托管身份服务减少密码实现，关系型表存放用户事件；只是候选方案，地区、运维和预算未确认。备选 Workers + D1 + 独立身份服务需同样通过授权/同步契约。不得仅因候选服务存在就开通付费资源。[Supabase 官方身份与 RLS 资料](SOURCES.md#src-auth)

静态首页、字典正文、场景和文章不依赖登录 API；后端故障不能让读字和游客练习停止。正式构建更换当前 `single-page-application` 未命中策略，返回真实 404；Cloudflare 默认 HTML 规范化可能给出 307，永久迁移不能只依赖默认行为，需显式规则与实际响应测试。[Cloudflare 路由依据](SOURCES.md#src-cloudflare)

## 6. REQ-05｜真实数据、来源和模型

Phase 1 核心集冻结为 **旧 107 个唯一字 ∪ 原型 26 字 = 126 个唯一字**。这是迁移与教学起点，不是常用字排名或 HSK 全表。核心字与新增 HSK 字共用以下两级标准；“内容增强程度”与“能否发布”分开记录。

| 等级 | 内容标准 | 数量与发布方式 |
|---|---|---|
| Tier 1 黄金完整版 | Tier 2 全部基础内容，加专属插画、深入的 VisualNote 视觉助记和自然场景例句；事实与联想分别标注 | 首批增强目标 30–50 字，优先适合视觉教学的常用象形/会意字；首页与着陆页优先展示已完成条目。无词频依据时标“编辑精选”，不冒称排名 |
| Tier 2 标准可用版 | CC-CEDICT 导入并核对的拼音/英义；可用真实笔顺与静图；部件或独体结构说明；至少一条例词及短例句；一条经快速审读的原创英文助记；Information、来源与练习入口 | 其余核心字及 HSK 1–2 级关联字默认按此发布；不要求专属插画或长故事，满足标准即可 `indexable=true` |

126 字全体达到 Tier 2 即满足核心字内容门槛，不为凑满 30–50 个 Tier 1 推迟发布。若其中 30–50 字完成升级，剩余标准版实际为 76–96 字；这只是分层数量，不新增重复字页。升级沿用同一 URL、characterId 和学习记录。

允许 AI 批量起草英文一句话助记和原创例句，先自动检查拼音/目标字、重复模板和基础格式，再逐条快速过目；审核者/日期与生成批次可追溯，不要求用户逐页在聊天中确认。重点剔除错误拆字、凭空字源、词义不符和不自然英语；独体字如无可解释拆分，提供真实结构说明。标准版的轻量审核不等于跳过核对，也不以所有插画完工为条件。

缺少插画、长 VisualNote 或可选 Kanji 不导致 noindex；具体错音、错义、坏笔顺或未审 AI 草稿只影响对应条目，修复后再放行，其他成熟页继续发布。HSK 源清单完整性与已发布字页覆盖分别统计，不因一个增强条目缺失关闭整套字库。首发总页数由核心集与两版 HSK 首级的实际并集计算，字数、词数、页面数分开，不预报“几百页已被 Google 收录”。

| 数据 | 建议来源和版本规则 | 许可/验收边界 |
|---|---|---|
| 字/词英义与读音 | CC-CEDICT 官方下载包；实施时固定文件日期、格式版本、SHA-256，解析字头/读音/义项 | 本轮官方页列 CC BY-SA 4.0；附归属与同许可的派生数据说明，不将整站代码误判成同一许可；只取明确下载资源，不抓词典查询界面 |
| Unicode、变体、部首/笔画补充 | Unicode Unihan，固定一个明确发行版本和文件校验和 | 保留该版本 Unicode 许可；字段不能替代完整教学英义；不假定简繁一一对应 |
| Japanese Kanji 对应信息 | 锁定版本的 Unihan 候选字段及日本文化厅常用汉字表等可核验来源，逐条审核 | 字码、日语读音字段或繁体字形不能单独证明日语对应关系；常用汉字表不是全部日语汉字清单；见 [Information 依据](SOURCES.md#src-character-info) |

| 笔顺 | Hanzi Writer 渲染器 + hanzi-writer-data / Make Me a Hanzi 图形，固定包版本及上游 commit | 渲染器代码与笔画数据分别记许可；笔画数据按 Arphic Public License，不能笼统写 MIT；每个字验证 strokes/medians 数量与加载 |

| 语音 | 复用 `tts-v1` 及现有故事腾讯云静态音频；新增按词境生成并审核 | 不重复生成已有正确读音，不泄露腾讯云凭据；音频来源和文本版本可追溯 |
| 视觉联想/场景/文章 | HanziFun 编辑内容；保留原型插画生成来源 | 人工核对中文、拼音、英译、年龄适用性；事实与联想分别标注 |

上述来源逐条链接、已核实事项与尚未获取的版本在 [SOURCES.md](SOURCES.md)。**本轮没有下载并批准生产数据集**，因此不虚构包哈希、全量字数、覆盖率或许可证审查结果。HF-02 必须交付 `data/sources.lock.json` 和 `data/coverage.json`，未锁定字段不得用 `latest` 冒充。

## 7. REQ-06｜查字、搜索和详情

输入支持汉字、带调拼音、数字调拼音、无调拼音和英文释义；大小写及多余空格规范化，`ü` 与 `u:`/`v` 同组，但不能把 `lü` 和 `lu` 当同一音节。有调查询先精确匹配，再提示放宽；多音字分别显示读音及例词。NFC 处理，不用有损转换合并不等义的字。

搜索结果按“汉字/词 → 卡组 → 场景/文章”分组，精确字形优先，结果显示数据范围；输入最多 100 个字符，输出转义。未知输入显示可操作空态，加载失败显示重试；未收录字提供查找建议，不生成看似完整的假字源页。

单字页主体顺序：**读音与释义 → 视觉记忆与拆字 → 笔顺动画和完整逐笔静图 → 常用词与例句 → 简繁和易混字 → 练习、打印、收藏**。每字至少一个审核过的例词和例句；常用词与拆字可以先在页内解释，不要求先开独立词语或部件专题。打印入口只连接实际可用的资源；首版仍是既定 6 字样本，不假称 126 字都有打印包。简繁概览与下文 Information 读取同一份数据。

Information 是补充信息区，桌面放在正文旁，手机放在字形/读音概览之后。主要字段直接可见，不藏在鼠标悬停提示中：

| 英文标签 | 展示内容与规则 |
|---|---|
| Pinyin | 当前读音的带调拼音和听音入口；多音字分别对应义项，切换后同步更新；提供 Pinyin Chart 入口 |
| Traditional Chinese | 已核实的繁体对应字形；同形注明相同；一对多按语境解释。浏览繁体字页时同时给 Simplified Chinese 对照 |
| Japanese Kanji | 有审核依据才显示日语对应字形与必要说明；使用 `lang=ja` 和适合日语的字体；中文拼音不标成日语读音 |
| Radical / Stroke count / Structure | 当前字形的部首、笔画数和结构；部首与视觉拆字分清，不套用另一字形或地区的笔画数 |

Kanji 首版只做字形关联及必要说明，不承诺中文和日语同义同音，不默认增加音读/训读教学。没有核实关系时省略该行；真实核实记录和覆盖统计仍需交付，不能用全部隐藏替代完成数据工作。Unicode 等技术字段可放可展开的详细信息，不作为主要学习内容。[核对依据](SOURCES.md#src-character-info)

记忆联想单独标为 Visual memory cue；历史字源只有有证据时才展示。收藏状态和“练过”分开：移除收藏不删除学习历史，练过不会自动等同于收藏。关联字形只有在已有可用字页时才生成链接；否则显示文字说明，不制造空页面。

基础解释与主要链接预渲染；JS 或音频失败仍可读。结果按批次/分页呈现，不能把全量 CC-CEDICT 与笔画库一起塞进首页脚本。查找 `/dictionary/水/` 与 `/stroke-order/?char=水` 使用同一稳定 ID。

## 8. REQ-07｜视觉、独立笔顺页、拼音表与声音

笔顺支持播放、暂停/继续、上一笔/下一笔、重置、速度选择与 `n / total`。支持已批准的实际字形数据，不只是木的四条手画线。完整逐笔静图与动画都可查看，减少动态效果或 JS 不可用时仍保留静图；缺资源、加载失败、字形差异均有解释，不能无限转圈。初次仅加载当前字笔画，缓存按版本失效。

`/stroke-order/` 独立提供选字、播放/逐笔/速度控制、基础笔顺规则与字形标准说明，链接所选字的完整字典页；与单字页共用笔画数据和播放组件。单字页 `?char=` 跳转保持选中字，不将工具搬到 `/dictionary/stroke-order/`，也不为每个字复制一套薄内容笔顺页。

`/pinyin-chart/` 的首版内容：

1. 可读取的拼音表和简短使用说明，按声母、韵母组织合法音节；零声母及特殊拼写单独处理，无效组合留空。按固定审核清单显示覆盖范围，罕见音节或儿化变式若未覆盖须说明。
2. 点击音节查看带调拼音、可用声调发音、审核例字/例词和英义。提供四声及轻声的简短说明；只启用有真实审核音频的播放按钮，不假定每个音节都有五种常用读法。轻声用词境示范。
3. 支持输入音节与按声母/韵母筛选；规范化与字典共用，区分 `lu` / `lü`，正确处理 `j/q/x` 与 `ü` 的拼写、`y/w` 形式、`iu/ui/un` 等。拼音属于发音符号，不用英语字母名称朗读冒充普通话发音。
4. 例字链接已发布的单字页，“查看这个读音的汉字”链接 `/dictionary/pinyin/` 的对应分组；没有已收录例字时可听发音并解释覆盖范围，不自动生成空字页。单字 Information 反向链接拼音表中的音节。
5. 桌面使用可操作表格；手机可按声母分组展开，键盘可定位、选择和播放，整页不因宽表溢出。正文与音节标签预渲染；音频失败保留拼音与说明，不一次下载全套音频。首版不建立每个音节的独立详情路由。

语音由明确用户动作触发；同一时刻只播一项，换卡、离页、关声音应停止。静态音频优先，非故事字词可用浏览器普通话朗读兜底并说明可用性；无合适语音时保留拼音。多音字必须用对应词境读音，不能把旧字卡的“字+组词”整段录音当成裸单字音频。故事课音轨和 TTS 约束遵循原流程，不能新增浏览器生成音频替换正式课旁白。

拼音表音频单独绑定音节/声调，首次公布前完成普通话审核；浏览器朗读一个拉丁字母拼写或无声调音节不能作为合格兜底。HF-02 提供音节及音频清单，HF-04 完成页面与交互，HF-08 检查独立索引和可访问性。

## 9. REQ-08｜HSK 2.0 / 3.0 版本与覆盖

`/academic/hsk-2/` 与 `/academic/hsk-3/` 是两个不同体系，永久保留入口，不增加同义 `/dictionary/hsk-*` 页面。

| 页面 | 初始明确基准 | 不能混淆 |
|---|---|---|
| HSK 2.0 | 官方资源中心《汉语水平考试（HSK）词汇表（2015版）》，1—6 级；实施时保存实际 XLSX 及元数据 | 官方词级别与“从这些词提取的字”不同；派生字级别标 `derived-from-vocabulary`，不伪称官方独立字表 |
| HSK 3.0 | 官网当前大纲 PDF：2025-11 发布，封面写 2026-07 实施；按实际文件及修订时间锁定 | 不等同于 GF0025-2021；分词汇、认读字、书写字等列表，不能合并成一个等级字段 |
| 2021 标准参考 | 教育部 GF0025-2021，三等九级，2021-07-01 实施 | 可作为单独 reference edition，不能直接当当前考试词表 |

2026-10-23 核查时，官网首页公告说明 HSK 3.0 将于 **2026-12-13** 全球正式开考。大纲封面实施日期、试行和实际考试启用日期需分别存储；上线时再次核对官网，不向用户承诺任意考点/日期的适用版本。[官方证据](SOURCES.md#src-hsk)

Phase 1：两体系各完成**首级词表及关联字**；新大纲的认读/书写清单分别展示；新增字按 Tier 2 快速交付。每个列表分母来自锁定源文件，自动计算“范围映射 X / 源文件 Y”“Tier 2 可用字 / Tier 1 增强字”，同时显示实际教学覆盖。尚无实质内容的其他级别占位页 noindex；已完成的首级与成熟字页正常开放索引，不等待高级词库或更多插画。

Phase 2 / HF-14：第一批优先把两版本扩至 **2 级**，随后按级扩充 HSK 2.0 的 1—6 级和 HSK 3.0 的 1—6、7—9 合并级别。每批合格就发布，首个扩充批次不等于整包全量完成，也不要求账号同步；高级范围可持续迭代。源文件若只给 7—9 联合表，不虚拆出 7/8/9 三套词表。区分新增表与累计表，记录重复、异体、多音与源表修订。每级自动全量计数、去重、引用完整性检查；人工抽查至少 30 条或该级全部（取较小值），覆盖边界行、多音字、跨级重复与拼音异常；新助记按 Tier 2 逐条快审。

## 11. REQ-10｜游客记录与学习中心

## 14. REQ-13｜跨设备同步与 API

认证服务的 subject 是用户身份唯一可信来源；客户端 `userId` 不能决定数据归属。账号数据建议实体：UserProfile、SavedItem、ReviewEvent、ProgressProjection、PracticeSession、ImportBatch、DeviceCursor；所有个人表和查询按 owner 隔离，若使用 Supabase 启用并测试 RLS。

建议同源 API 契约（最终存为 OpenAPI 或等价机器可验证文件）：

| 接口 | 行为 |
|---|---|
| `GET /api/me` | 当前身份/资料，未登录返回 401 |
| `POST /api/auth/start`、回调、`POST /api/auth/sign-out` | 认证适配，重放/CSRF/回跳校验 |
| `POST /api/sync/events` | 一批不超过 100 个事件；逐项 ack/rejected/conflict，幂等键与数据库唯一约束 |
| `GET /api/sync/changes?cursor=...` | 不透明递增服务器游标、分页、删除 tombstone |
| `PUT/DELETE /api/me/saved/{itemId}` | 带 operationId、baseRevision；幂等收藏/删除 |
| `GET /api/me/summary`、`GET /api/me/sessions?cursor=...` | 从事件投影读统计；分页，不暴露别人的记录 |
| `POST /api/me/imports` | 确认后的游客批次，服务器去重和权限校验 |
| `GET /api/me/export`、`DELETE /api/me` | 导出与删除，删除需重新验证 |

错误体统一 `code/message/retryable/requestId`；400/422 参数或数据异常，401 会话失效，403 越权，409 版本冲突，429 节流，5xx 可重试。返回 `serverTime`；对学习时间、未来时间、过大 payload、未知 ID 校验。日志不写邮箱、原始姓名、token、生词内容。

同步流程：本机事务写入 → outbox pending → 上传 → 收 ack → 拉变化 → 确认后移除 pending。指数退避并有上限/抖动；刷新和重发不会丢失未确认事件。显示“本机已保存/同步中/已同步/需重新登录/失败可重试”；不把 HTTP 发出当成已同步。

冲突原则必须测试：

- ReviewEvent 追加且以 `(userId,eventId)` 去重；不接受覆盖整份 Progress 的客户端请求。
- 服务器事务依据 card 的 revision 判定调度。正常新事件推进一次；基于过期 revision 的离线事件保留为历史，返回 conflict 和当前排程，不再推进 known。若过期事件为 again，保守安排一个补充复习（不能把到期推迟），并记录冲突原因。两设备并发不能连续推进两级；不要求设备间任意到达顺序产生相同毫秒 dueAt，但要求同一服务器事件日志重放一致、最终所有设备收敛。
- 客户端异常时间不能成为“最新”的唯一依据；服务器接收序号与有效 occurredAt 都保存。严重时钟偏差展示修正提示。
- 收藏删改使用 revision 与 tombstone；旧设备的 stale save 不复活已删除项，用户看到冲突可明确重新收藏。主动新操作基于新 revision 后才能改回。
- 游客转账号必须展示导入数量和选择“合并/暂不导入”，操作幂等；账户已有进度优先保留，旧摘要不能覆盖新排程。
- 在共享设备上切换 A→B，A 的 outbox 仍只能上传至 A；B 不继承 A 的缓存。删除账号后的旧 outbox 不得复活该账号数据。

## 20. REQ-19｜SEO 与可发现性

2. 发布状态驱动索引：正式首页、达到 Tier 2 或 Tier 1 的字页、具有真实范围列表和学习内容的 HSK 页、正式工具/文章可索引；缺插画/长助记不设 noindex。搜索、个人页、登录、动态练习状态、占位工具/样文及未审草稿 noindex；具体错误只隔离受影响页。404 返回 404，私人 API 返回对应 401/403，不用 robots 充当鉴权。
3. staging 优先访问控制并加 noindex；若需要搜索引擎读取 noindex，不能同时用 robots Disallow 阻止读取。生产从 allowlist 生成索引策略，禁止把原型 `Disallow: /` 或全站 `noindex,nofollow` 带上线。
4. sitemap 只列 canonical、200、公开且可索引的 URL；真实内容修改才更新 lastmod。查询/排序/多重筛选不生成海量索引页。
   2026-10-28 Owner明确开放Kids、英文故事目录/介绍、练习纸及公开Flashcards入口/目录/固定卡组的索引。公开卡组输出静态介绍与字页链接；个人收藏、账号、教师预览仍noindex。含session参数的闪卡URL由head脚本在解析页面时设置noindex，canonical继续回不带参数的主地址，不把会话组合加入Sitemap；这不是服务器鉴权或服务器按query返回不同HTML。未完成的文化工具不因新增导航链接自动转为可索引。
5. `lang=en/zh-CN` 按正文设置；只有等价翻译页才配互相回链的 hreflang。英文营销首页与旧中文闪卡应用不等价，不硬配 hreflang。[Google 多语言依据](SOURCES.md#src-seo)
6. 可做 WebSite/Organization、BreadcrumbList、真实 Article 等符合当前规范的结构化数据；可见内容与标记一致，不造评分。首页六个 FAQ 保留为真实、可读取的问答正文：问题清晰、先直接回答、必要时链接对应功能，覆盖用户实际的长尾问题，随阶段更新，不堆关键词。Google 已于 2026-05-07 停止 FAQ 富结果，FAQPage 标记不作为发布前置或富结果验收目标；关注正文、正常内链和可抓取性。以便于搜索及 AI 系统理解/引用为内容目标，但不承诺 ChatGPT Search、Perplexity 或 Google AI Overviews 必然收录/引用，不把特殊 schema 或 llms.txt 作为必需项。[Google FAQ 与 AI 搜索说明](SOURCES.md#src-seo)
7. 旧诊断中的搜索量、排名、GSC 数字是参考时间片，不是本轮验证的现状；不据“0 搜索量”删除用户确认的人群方向。不买外链、不承诺排名，也不自动提交 Search Console。

独立页规则：成熟的 `/stroke-order/` 与 `/pinyin-chart/` 各有自己的 canonical、title、H1、说明正文和 sitemap 条目，分别承接书写与发音需求；不 canonical 到 `/dictionary/`。`/stroke-order/?char=水` 保留选字交互，canonical 指向 `/stroke-order/`，不把参数组合加入 sitemap。拼音表的选择/筛选只作为页内状态，不制造大量可索引 URL。`/dictionary/pinyin/` 保留按读音查字的独立正文及列表，不复制整张拼音教学表。单字页继续使用自身 canonical。该安排是产品与索引设计，不是根目录 URL 必然提高排名的承诺。[canonical 依据与边界](SOURCES.md#src-seo)

## 22. REQ-21｜隐私、安全与可观测性

不收集完成当前学习所不需要的个人信息；Phase 1 无登录凭据采集。查询、姓名、生日不默认记录到分析日志。只在用户真实可读的隐私说明下接入必要分析；未确定运营地区和同意机制前不引入广告/跨站跟踪。
