# 来源升级审阅模板

- 日期、操作者、代码提交：
- 来源 ID、旧版 → 新版、旧/新原包 SHA-256、实际 URL：
- 许可原文/范围变化、需替换或排除的具体字段：
- 上游新增/删除/变更条数；核心字/读音/义项/简繁关系变化：
- 笔画路径/中线数量与字形/地区变化：
- 拼音范围版本、声调/例字变化、审核音频受影响范围：
- 稳定 ID 是否保持，读音/义项拆分的显式迁移：
- 旧教学位置及“睛”第 19/87 位置还原结果：
- coverage 的核心/HSK/Tier/音频/拼音分母与分子变化：
- 英义、语境、地区字形、Kanji、20 字以上笔画抽查及逐项听审记录：
- `data:build`、`data:validate`、`npm test`、本地浏览器命令/环境/截图：
- 结论、未通过项、受影响条目、回退到旧来源的方法：

执行 `node scripts/fetch-content-sources.mjs --refresh` 后生成的 `source-upgrade.json` 保存锁文件前后快照；规范化字段变化仍须通过 `git diff -- data/` 审阅。不得以“哈希变了但测试绿了”替代内容复核，也不能把一次升级的确认扩展成今后所有来源更新的授权。
